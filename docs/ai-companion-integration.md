## 接入条件

网页仍通过 `MeguriGatewayController` / `MeguriGatewayService` 的 `/api/v1/meguri` 接入。网站登录态用于 ADMIN 鉴权；Core token 和身份头由服务端添加。没有浏览器直连本机文件或将密钥下发前端。

服务端应配置 `MEGURI_GATEWAY_ENABLED`、`MEGURI_CORE_BASE_URL`、`MEGURI_CORE_TOKEN` 或 `MEGURI_CORE_TOKEN_FILE`、`MEGURI_OWNER_USER_ID`、`MEGURI_SPRITE_DIR` 和默认立绘。密钥取自既有私有配置；正式记忆策略由 `MEGURI_FORMAL_MEMORY_ALLOWED` 控制。默认网关为关闭状态。

本次未部署或修改远程服务。无需授权的远端 Core 健康请求返回 HTTP 401，证明入口要求鉴权，但不能确认内部模型／记忆在线；本机 `127.0.0.1:18080` 在检查时未提供健康响应。上线验收需要在真实 ADMIN 登录态下确认 bootstrap、立绘、一次真实聊天及重连。网站服务器属于 `111.228.35.186`。

## 按依赖补齐 AI

1. **协议与可靠恢复。** 网站网关发送平铺 `user_id/client_id/session_id` DTO，事件工具只做 SSE 游标重连。当前桌宠 Java `RuntimeWebController.parseTurnRequest` 仍保留 legacy 路径，因此不能仅凭新版 SDK 推断现有网关必坏；但网站尚未支持新版 `/v1/hello`、协商后的嵌套 identity、能力修订和会话 snapshot。先确认远端 Core 版本，再在服务端实现握手、能力白名单和过期游标 snapshot 恢复，兼容验证后迁移。
2. **会话历史。** 普通聊天有服务端历史；Meguri 页面目前只持久化会话／进行中的回合标识与展示偏好，完成后的聊天行只在运行时。增加受鉴权的服务端历史或 snapshot 查询，再提供恢复／导出入口。避免把聊天正文塞进 localStorage 当作历史数据库。
3. **记忆的可见性与控制。** 网站的通用 MemoryOS scope 和 Meguri Core 正式记忆是不同来源。为 Meguri 增加自己的读取、审阅、删除和来源说明，并由服务端绑定当前 owner 身份。公开访客不能看到或写入个人记忆。
4. **页面辅助。** 有了稳定能力协商后，增加用户显式触发的文章总结、待办梳理和日程建议。只提交用户选中的文本；写入待办等动作先展示可审阅的内容，再调用网站已有 API。不要默认收集整页、私有账单或浏览轨迹。
5. **可选语音。** 桌宠有本机 TTS 和本地语音服务；现有网站网关明确声明 `voice=false`。网页朗读可以先做用户主动选择的浏览器能力；高质量 Core TTS 需鉴权的音频端点、取消／播放状态与移动端用户手势处理。
6. **本机能力配对。** Everything 搜索、窗口控制、文件工具和桌面通知依赖本地运行环境。后续沿用已存在的桌面配对／控制边界，为每项操作提供明确授权、可见状态和失败反馈；不要从网页直接复制桌面权限。

每个后续阶段应独立建 OpenSpec change，并以真实接口和权限测试验收。当前接入、恢复 UX 和能力评估属于本次交付；上述后续能力不被标记为已实现。
