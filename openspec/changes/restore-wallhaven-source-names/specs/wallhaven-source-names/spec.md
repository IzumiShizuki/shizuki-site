## Purpose

Keep recognizable artwork names visible while browsing Wallhaven and carry those names into wallpaper imports, instead of replacing them with category labels and provider IDs.

## ADDED Requirements

### Requirement: Wallhaven discovery preserves descriptive source names
The system SHALL use a descriptive Wallhaven source name as the discovery title and SHALL NOT prefix that title with a wallpaper category. When no direct title is available, the system SHALL use a readable final path segment from the source URL, then descriptive tags, and only then a provider-and-ID fallback. Category information SHALL remain available as metadata.

#### Scenario: Source URL contains a descriptive work name
- **WHEN** a Wallhaven result has no direct title but its source URL ends in a descriptive path segment
- **THEN** discovery displays that segment as the result title without a category prefix

#### Scenario: Source URL has no usable name
- **WHEN** a Wallhaven result has no direct title and its source URL has no descriptive path segment
- **THEN** discovery uses descriptive tags as the title, or a Wallhaven-and-ID fallback when no usable tags exist

### Requirement: Wallhaven imports retain the resolved source name
The system SHALL persist the same resolved source name used by discovery when the import title is blank or is a legacy generated category-and-ID placeholder. The system SHALL preserve an intentional non-placeholder title supplied by the user.

#### Scenario: Import title is blank or generated by an older client
- **WHEN** a Wallhaven import omits its title or submits a legacy category-and-ID placeholder
- **THEN** the imported wallpaper uses the resolved source name from Wallhaven metadata

#### Scenario: User supplies a custom import title
- **WHEN** a Wallhaven import contains a non-placeholder title entered by the user
- **THEN** the imported wallpaper keeps that title
