## Context

账户使用 MyBatis 逻辑删除，历史内容通过用户 ID 引用账户。认证由 Sa-Token access 会话和 Redis refresh 会话组成；个人中心已有统一按钮、提示和折叠分区。

## Goals / Non-Goals

**Goals:** 只允许本人发起注销，清除可登录身份和私密绑定，注销后旧会话不可继续使用；统一缺省头像。

**Non-Goals:** 不级联删除公开文章、媒体及历史业务记录，不改作者头像或音乐封面，不自动部署功能。

## Decisions

1. `DELETE /api/v1/me/account` 接收 `confirmation: 注销账号`，服务端从登录上下文获取唯一目标 ID，不接收外部指定用户 ID。使用专用事务服务更新账户为不可恢复的匿名墓碑，释放用户名和邮箱，并清空密码、头像、组和权限，然后逻辑删除。保留主键避免破坏历史引用。直接物理删除需要跨模块级联，影响范围过大。
2. 身份、偏好、OAuth 事务、第三方音乐凭据和通知联系人在同一数据库事务内清除，绑定关系和凭据采用物理删除以释放唯一键。锁定活跃账户以串行处理管理员注销，拒绝删除最后一个管理员。
3. 在数据库提交前撤销所有 refresh 和 access 会话；撤销失败使数据库事务回滚。被提前退出的用户可以重新登录重试。Token 签发和鉴权仍以活跃账户查询兜底。
4. 注销 UI 使用现有视觉语言下的共享面板，先展示后果，再输入确认词，单次提交期间禁用按钮，失败保持登录态与错误提示，成功后才清本地会话并跳转。桌面与移动共用此面板。
5. 使用随包发布的 SVG 人像和共享头像组件处理空值及加载失败，避免外部请求和字体图标差异。自定义头像继续优先显示。
6. navidias 运维清理仅在个人服务器上精确比对用户名、昵称或 OAuth 标识，唯一命中后执行同等匿名化与会话撤销，并在不含敏感信息的记录中保存验证结果。不会把一次性用户名写入应用数据库迁移。

## Risks / Trade-offs

- [历史内容仍存在] → 注销提示明确说明公开内容和历史记录保留，仅匿名化账号身份。
- [数据库与 Redis 无分布式事务] → 撤销失败回滚数据库；提前退出不影响重新登录。鉴权和签发均拒绝逻辑删除账户。
- [未知第三方身份或重名] → 运维步骤先读后写，发现多条候选时暂停针对性删除，其他实现继续。

## Migration Plan

不新增字段或修改既有迁移。功能通过常规构建部署；代码可回滚，已注销账号不可恢复。当前交付只做本地提交及用户明确要求的 navidias 数据清理。
