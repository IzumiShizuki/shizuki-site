## Context

Vue 普通音乐模式已经有网易云账号绑定、Meting 多平台搜索和共享音频输出。网易云 NCM sidecar 固定为 API Enhanced 4.32.0，Folia 直接使用它。普通播客区仍混用 ASMR 与静态占位，普通红心使用本站 LIKED 歌单，来源导入创建静态副本。QQ/酷狗账号代理尚未部署（deploy/folia/README.md）。动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 复用服务端加密 Cookie、现有 NCM 和共享队列；实时读取平台歌单与喜欢列表；把上游失败与账号切换纳入验证。

**Non-Goals:** 安装新的平台服务、删除历史用户数据、重新设计整个播放器。

## Decisions

1. 在网易云客户端增加结构化账号歌单、喜欢列表、显式 like/unlike、声音推荐/节目与私人 FM 方法。上游响应必须有成功 code 和预期字段，异常信息不得暴露 Cookie。Mutation 使用 POST、明确 desired state 与时间戳，避免缓存和重复切换。
2. 新增独立平台音乐服务与 controller，统一平台 playlistCode 命名为 `account_netease_<id>`、播客为 `podcast_netease_<id>`。主媒体服务将这些编码路由到平台服务，并整合平台侧栏；平台歌单不再写入本站副本。真实本地自建歌单保留，历史导入副本在平台已绑定时去重隐藏。
3. 保留旧默认歌单管理 API 和存量数据以供兼容，但用户音乐页、迷你音乐库与初始选择不再注入它。无可用歌单时显示空态。避免数据库迁移与删除用户内容。
4. 前端以 `provider:trackId` 保存喜欢状态；当前账号的受限 fetch、请求版本和 pending 集合防止串号与并发写。先收到平台成功结果再更新红心，失败显示明确错误。QQ 等暂不可写的平台返回能力错误。
5. 播客节目用 mainSong 的真实歌曲 ID，统一交给现有网易云账号解析和共享播放器。私人 FM 独立加载，声音支持推荐与关键词搜索，ASMR 保留原独立入口。
6. Folia 已自行执行平台点赞；其状态通知只触发喜欢列表刷新，避免同一操作执行两次。普通模式点赞完成后发送已确认的状态，更新 Folia 账号缓存；账号刷新事件同时使迷你音乐库失效并在打开时重新读取。

## Risks / Trade-offs

- [上游登录过期或限流] → 失败可重试，保留既有内容，拒绝假成功，测试错误 code 与无效响应。
- [实时歌单增加请求] → 侧栏只读取摘要，进入歌单时再读取曲目；不在每次点赞后重载所有歌单。
- [私人 FM 只返回一批歌曲] → 提供再次获取按钮，复用共享队列。
- [平台能力不齐] → 当前仅网易云具备已部署账号 API，其他平台继续搜索播放并明确报告账号点赞暂不可用。

## Migration Plan

本地先完成后端/前端验证与 OpenSpec 严格校验并提交。用户已明确要求发布到 `111.228.35.186`；在当前线上基线的独立干净 checkout 中只应用此次音乐提交及 Folia 补丁，复用现有生产参数构建后端 JAR、主站及 Folia。上线前保存已验证的应用/配置/数据库/卷恢复点和三个运行镜像，检查磁盘容量；先发布后端，再发布前端与 Folia，并验证健康、资源身份和音乐 API。失败时恢复镜像与应用文件。沿用现有 NCM 与私有配置，数据库无迁移。Git 远端推送不属于本次部署授权范围。

容量审计发现根盘不足以保留额外的完整备份与远程构建工作区。回收经过白名单核对的闲置构建缓存；新完整恢复点先在 `/dev/shm` 私有目录创建。进一步核对根卷 ext4 发现约 4.7 GB 系统预留块；调整为 3% 并保留约 3.2 GB 系统应急预留后，将完整恢复点持久化至原 `/opt/shizuki-site-backups/` 并逐文件校验 SHA-256，校验完成后才允许切换服务。服务器另外保留旧镜像标签、此次修改文件的回滚归档和完整备份位置/哈希索引；不删除历史恢复点或数据卷。新镜像复用原运行环境，加入精确本地构建的 JAR 与变化后的静态文件，保留旧哈希资源以支持已打开的页面。Folia 完整对应源码与许可证在 `/music/source/` 提供公开下载。
