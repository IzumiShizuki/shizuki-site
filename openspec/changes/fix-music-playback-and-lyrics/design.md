## Context

当前播放引擎会在自动播放时刷新已有音频地址，但刷新请求没有把绕过服务端缓存的标志传递给后端；媒体 `play()` 或 `error` 事件发生后才进行一次强制刷新。音乐页面在返回 `false` 时直接弹窗。后端的通用缓存分支位于网易云账号源选择之前，且网易云账号客户端仍生成公开 `song/media/outer/url` 地址。账号歌词只映射 `lrc`，而前端紧凑播放器和全局字幕条没有完整消费翻译及相邻行上下文。

## Goals / Non-Goals

**Goals:**

- 将缓存播放失败恢复纳入同一次点击流程，并确保刷新请求真的绕过过期的服务端缓存。
- 让已绑定网易云账号的播放解析优先使用账号 Cookie 和账号流地址接口，保留现有 Meting 回退策略。
- 在后端响应、前端时间轴和跨模块字幕展示之间保持原文/翻译/上下句的一致数据形状。
- 用前端单元测试和后端集成/单元测试覆盖三类回归场景。

**Non-Goals:**

- 不更换 Meting、网易云或缓存基础设施，不新增第三方依赖。
- 不改变用户账号绑定流程、源模式配置含义或已有的用户手动字幕模式选择。
- 不尝试绕过网易云账号本身没有的会员权限；上游不给地址时只能按既有回退策略处理。

## Decisions

1. **把刷新语义显式传递到后端。** 前端首次自动播放已有地址的可解析曲目时同时设置本地强制解析和请求体 `forceRefresh`；媒体加载/播放失败时继续使用一次带 `forceRefresh` 的静默恢复。这样能区分“需要解析”与“必须绕过缓存”，并避免依靠第二次用户点击。

2. **账号源优先于通用缓存。** 在后端读取缓存后，先判断当前用户是否绑定并启用了网易云账号源；账号优先/账号仅用模式下跳过匿名或通用缓存分支，进入账号解析。账号解析失败时仅在账号优先模式回退到原有 Meting 流程，账号仅用模式保持失败语义。

3. **使用网易云账号流地址接口并保留安全回退。** `NeteaseCookieProvider` 使用 Cookie 请求网易云的歌曲播放 URL 接口，优先选择会员/高音质返回的有效 URL；只有上游没有返回地址时才回退到现有公开外链。歌词同时读取 `lrc`、`tlyric` 和可用的 `romalrc`，通过扩展解析结果携带到服务层。

4. **扩展现有 lyric context，而不是另建一套字幕状态。** 在 `usePlayerEngine` 的时间轴上为 `prev/current/next` 增加 translation 字段，`MusicPlayer` 和 `App` 全局字幕条共享该 context；详细播放器继续使用现有 `lyricRenderMode` 选择器。

5. **失败反馈延后到最终结果。** 播放器内部对首次媒体错误和一次刷新重试不产生 UI 错误状态；页面仅在引擎确认所有恢复路径均失败后显示现有提示，避免把可恢复的瞬时错误暴露给用户。

## Risks / Trade-offs

- [Risk] 网易云上游接口可能返回短时有效或地区受限 URL → 继续在媒体错误时执行一次强制刷新，并限制为单次重试。
- [Risk] 账号流地址包含用户授权上下文 → 账号源跳过通用缓存，服务端日志不记录 Cookie/完整地址，缓存策略仍沿用现有存储配置并由测试确认来源标记。
- [Risk] 翻译时间戳与原文不一致 → 复用现有最近时间戳/行序对齐工具，保留原文时间轴并对未匹配翻译留空。
- [Risk] 全局字幕条变高后影响其他页面布局 → 采用紧凑的两行当前/下一句结构，并为缺失行保留空位，配合前端构建和组件测试验证。

## Migration Plan

1. 发布后端账号播放与歌词字段改动，再发布前端刷新参数和字幕渲染改动；两者保持向后兼容，缺失新字段时前端继续显示原文。
2. 部署后观察 `MUSIC_RESOLVE_PLAYBACK_STAGE_DONE`、账号源及媒体恢复日志，确认会员曲目来源为账号源且缓存失败不重复告警。
3. 回滚时恢复前后端版本即可，不需要数据库迁移；新增响应 metadata 字段和请求字段均为可选。
