## Why

生产站点的默认音乐歌单能够正常返回曲目信息，但播放地址和歌词地址为空，导致页面看似在线却无法实际播放。当前仓库还缺少一份能让后续 Agent 快速区分入口、后端、Meting、账号源、缓存和上游版权限制的生产运维手册，因此同类故障难以稳定复现、定位和验证。

## What Changes

- 建立音乐模块生产运维手册，记录架构链路、健康检查、常见症状、诊断顺序、修复边界、回滚与验收方法。
- 提供可自动运行的生产音乐冒烟检查，验证站点、后端、Meting、默认歌单以及真实曲目播放解析，而不只检查 HTTP 存活。
- 定位 `111.228.35.186` 上音乐链接为空的实际原因，并对生产配置或服务实施最小、可回滚修复。
- 为本次事故保留脱敏的根因、变更和验证记录，避免泄露 Cookie、Token、数据库口令或完整临时播放 URL。

## Capabilities

### New Capabilities

- `music-production-reliability`: 规定生产音乐链路的可播放性检查、故障诊断、修复安全边界与验收标准。

### Modified Capabilities

无。仓库当前没有已归档的音乐生产可靠性主规格。

## Impact

- `deploy/` 下的运维文档和音乐冒烟检查脚本。
- 个人站服务器 `111.228.35.186` 上的 `shizuki-site` Docker Compose 服务、环境配置和运行状态。
- 可能影响 Meting sidecar、音乐后端播放解析及默认歌单缓存；不涉及 `111.228.52.91`，不改变用户账号授权数据，也不记录敏感凭据。
