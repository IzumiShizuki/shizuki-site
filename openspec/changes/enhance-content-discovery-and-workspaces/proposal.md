## Why

本站已有丰富的写作、音乐、相册、动态与作者管理能力，但 Hash 路由无法向普通分享抓取器交付文章内容与元信息，博客检索不覆盖正文，手机阅读和各内容工作区的展示也需要更清楚的层次。本次落实 witchBlog 对照调研中用户选定的 SEO、分享、正文搜索、移动阅读，并统一强化既有内容表面。

## What Changes

- 增加服务端公开阅读/分享页面、公开内容站点地图与 robots，初始 HTML 包含可阅读内容、canonical、Open Graph、Twitter 与结构化数据，保持现有 Hash 应用入口兼容。
- 为文章增加正文、多词检索和安全的结果片段，使用现有发布/访问约束，撤稿与更新即时反映。
- 完善文章分享入口、移动目录/工具栏、返回保留筛选和位置、长内容溢出与安全区行为。
- 委托本地 Claude 强化文章编辑器、音乐、相册、动态和作者工作台的前端展示，沿用现有主题、数据与操作，改善编辑状态、媒体封面、信息层次及空/错/加载状态。
- 增加相应行为测试、生产代理配置与操作说明，完成本地验证和 Commit。

## Capabilities

### New Capabilities
- `public-content-discovery`: 服务端公开阅读/分享、元信息、站点地图与可见性规则。
- `post-body-search`: 受权限约束的正文和多词检索及结果片段。
- `content-workspace-presentation`: 写作、音乐、相册、动态与作者工作台的统一展示增强。
- `mobile-content-reading`: 手机阅读导航、目录、长内容、安全区及返回状态。

### Modified Capabilities

无。当前主规格目录没有可直接修改的对应规格，以上新增 delta 记录本次行为契约。

## Impact

- 后端：content-module、共享文章响应模型、单体公开访问配置。
- 前端：Vue 页面/媒体组件、分享与阅读状态工具、文章搜索反馈；本地 Claude 仅负责约定的前端文件。
- 部署：Nginx 与 Vite 公开页面代理；只准备配置，不执行部署或 git push。
- 数据：优先复用现有 Markdown 缓存批量查询，避免新增外部搜索服务或私密配置；公开输出不得依赖登录上下文。
